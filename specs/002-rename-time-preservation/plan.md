# План реализации

1. Добавить регрессионные тесты для переименования заметки и папки, ожидающей записи сессии, перерыва и ошибок записи.
2. Зафиксировать RED на текущей реализации.
3. Перенести обработку rename на уровень плагина и последовательно обновлять все сохраненные пути.
4. Сохранять фиксированную длительность перерыва до успешной повторной записи.
5. Выполнить тесты, TypeScript check, lint, build и проверку diff.

Архитектурное решение: TimerService владеет общей очередью операций и обновляет связанные пути одним действием. Главный класс плагина только принимает глобальное событие vault rename и запрашивает обновление overlay.
