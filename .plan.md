# План: закреплённая шапка с бегущей задачей в оверлее

## Что делаем
Когда таймер запущен на задаче из открытой заметки, сверху оверлея появляется
закреплённая (sticky) шапка: текст задачи + тикающее время + кнопка ⏹.
Нажали стоп (в шапке или в строке) — шапка исчезает.

## Почему это безопасно
- Ничего в логике таймера и записи в файл не меняется.
- Шапка строится в существующем `render()` из уже известных данных (`isRunning`).
- Исчезновение «бесплатно»: стоп пишет в файл → событие `modify` → ререндер →
  таймера нет → шапка не строится.

## Шаги

1. **`FocusOverlayView.render()`** — при обходе строк запомнить бегущую задачу
   (parsed + lineNo + rawLine). После цикла, если она есть, вставить в начало
   `built` блок `.tfa-pinned`:
   - текст задачи (`parsed.text`);
   - элемент времени (новое поле `pinnedTimeEl`, база = `elapsedSeconds`);
   - кнопка ⏹ → тот же `onToggleTimer(lineNo, rawLine)`.
   → verify: шапка появляется при старте, исчезает при стопе.

2. **`tickRunningTimer()`** — дополнительно обновлять `pinnedTimeEl`
   (та же формула, что для строки).
   → verify: время в шапке тикает синхронно со строкой.

3. **`styles.css`** — стили `.tfa-pinned`: `position: sticky; top: 0;`,
   фон `var(--background-primary)`, тонкая нижняя граница, z-index поверх строк.
   → verify: при прокрутке длинной заметки шапка остаётся сверху.

4. Сборка `npm run build` (или tsc) без ошибок, существующие тесты проходят.
   → verify: ручная проверка в Obsidian: старт/стоп из строки и из шапки,
   переключение таймера на другую задачу, таймер в другой заметке (шапки нет).

## Что НЕ делаем
- Никаких новых настроек (можно добавить потом, если попросишь).
- Не трогаем TimerService, core, формат файла.
- Шапка не показывается, если таймер бежит в другой заметке (можно обсудить).
